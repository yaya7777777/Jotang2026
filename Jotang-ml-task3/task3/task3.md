## 实践 1：简单计算链

对函数 `f(x, y) = (x*y + x**2)**2`，取 `x=2, y=3`。

### 计算图拆解

![计算图](results/chain.png)

```
a = x*y = 6
b = x^2 = 4
c = a+b = 10
f = c^2 = 100
```

### 链式法则（从后往前）

```
df/df = 1
df/dc = 2c = 20                     (f = c^2)
df/da = 2c * 1 = 20                 (c = a+b)
df/db = 2c * 1 = 20
df/dx = df/da*y + df/db*2x = 20*3 + 20*4 = 140
df/dy = df/da*x = 20*2 = 40
```

## 实践 2：神经网络的梯度

网络结构：`X → Linear(W1,b1) → ReLU → Linear(W2,b2) → Sigmoid → BCE Loss`

> 输入维度 (D=2)：每个样本包含 2 个特征
> 隐藏层维度 (H=4)：隐藏层包含 4 个神经元
> 输出维度 (1)：这是一个二分类任务，输出 1 个值（Logit）
> Batch Size (N)：一次训练输入的样本数量
> 激活函数：隐藏层使用 ReLU，输出层使用 Sigmoid（将输出映射为概率）
> 损失函数：BCE (Binary Cross Entropy，二元交叉熵)



### 形状标注

1. 第一层（隐藏层）
- 输入 X：形状为 (N, 2)，即 N 个样本，每个样本 2 个特征

- 权重 W1：形状为 (4, 2)，因为有 4 个隐藏神经元，每个神经元连接 2 个输入

- 偏置 b1：形状为 (4,)。每个隐藏神经元 1 个偏置，可以使用广播机制

- 线性输出 z1：公式为 z1 = X @ W1.T + b1
  - 这里 @ 表示矩阵乘法，X(N,2) 乘以 W1.T(2,4)，得到 (N,4)
  - 加偏置后，z1 形状为 (N, 4)

- 激活 h：公式为 h = relu(z1)

- 对 z1 中的每个元素应用 ReLU 函数：如果小于 0 就变成 0，大于 0 保持不变

- h 的形状保持 (N, 4)

2. 第二层（输出层）
- 输入 h：上一层的输出，形状 (N, 4)

- 权重 W2：形状为 (1, 4)，因为输出层只有 1 个神经元，接收 4 个隐藏层输出

- 偏置 b2：形状为 (1,)（广播机制）

- 线性输出 z2：公式为 z2 = h @ W2.T + b2
  - h(N,4) 乘以 W2.T(4,1)，得到 (N,1)
  - 这便是网络的 logit（未归一化的预测得分），形状 (N, 1)

- 概率 p：公式为 p = sigmoid(z2)

  - 将 logit 映射到 0~1 之间的概率值
  - 形状保持 (N, 1)

- 损失 loss：BCE 损失计算，最终得到一个标量（标量 mean）  

### 反向传播公式

```
dz2 = (p - y) / N            # BCE+Sigmoid 组合梯度（最核心简化），形状：(N, 1)
dW2 = dz2.T @ h
db2 = sum(dz2)
dh  = dz2 @ W2
dz1 = dh * (z1 > 0)          # ReLU 掩码，相当于“断开”了那些在前向传播中输出为 0 的神经元的梯度
dW1 = dz1.T @ X
db1 = sum(dz1)
```

### 运行结果（practice2_nn.py）

![practice2_nn](results/practice2.png)

**单个样本 (N=1)**：loss=0.661484
**小 batch (N=8)**：loss=0.628761

batch 时误差 ~1e-17 是浮点累加顺序差异，属于正常现象

## 趁热打铁

### 1. 前向传播时为什么要保存每一层的输入/输出？反向传播在哪里用到？和显存有什么关系？

反向传播的链式法则需要用到**前向时的中间值**，比如：
- 算 `dz1 = dh * (z1>0)` 需要前向的 `z1`（判断 ReLU 哪些位置激活）
- 算 `dW2 = dz2.T @ h` 需要前向的 `h`
- 算 `dW1 = dz1.T @ X` 需要前向的输入 `X`

如果前向不保存这些中间结果，反向就没法算
这就是为什么 PyTorch 默认会**为计算图缓存中间值**。

**和显存的关系**：网络越深、batch 越大，缓存的中间值越多，显存占用越高
这也是为什么大模型训练显存吃紧——不只是参数占显存，反向要用的中间值往往占据更大比
（为了减少显存占用，可以使用技巧：**gradient checkpointing**，即只保存少量检查点，其他需要时全部重算，用重算换显存）

### 2. 链式法则怎样把损失的梯度传回第一层权重？

沿着计算图**逐节点相乘**
以本题的 W1 为例：

```
dL/dW1 = dL/dz2 · dz2/dh · dh/dz1 · dz1/dW1
        = [(p-y)/N] · [W2] · [relu'(z1)] · [X]
```

每一步都是上游梯度 × 本地导数
从 loss 出发，每经过一个节点就链乘一项，一直传到最前面的 W1，只要每个节点会算自己的本地导数，整条链就能自动接上（这就是反向传播的**本质**）

### 3. BCE 与 Sigmoid 配合后，loss 对 logit 的梯度是什么？为什么方便？

推导过程：
```
p = sigmoid(z2) = 1/(1+e^-z2)
L = -[y·log p + (1-y)·log(1-p)]

dL/dz2 = dL/dp · dp/dz2
dL/dp = -y/p + (1-y)/(1-p) = (p - y)/(p(1-p))
dp/dz2 = p(1-p)
=> dL/dz2 = (p-y)/(p(1-p)) · p(1-p) = p - y
```

**结果：dL/dz2 = p − y**（batch 时再除以 N就好了）

方便之处：
- Sigmoid 的导数 `p(1-p)` 和 BCE 的分母 `p(1-p)` **正好约掉**，形式更简单了
- 不会再出现 `p→0/1` 时梯度消失的数值问题
- 代码里一行 `dz2 = (p - y)/N` 就搞定，不用分别算两个导数再相乘

这就是为什么"Sigmoid + 交叉熵"是“天生一对”（固定搭配）（Softmax + 交叉熵同理，梯度也是 `p - y`）

### 4. NumPy 梯度与 PyTorch 出现差异时，怎么判断问题出在哪？

按排查问题的顺序：

1. **损失的求平均方式**：最容易踩的坑，PyTorch 的 `binary_cross_entropy` **默认 mean**，NumPy 手算如果忘了 `/N`，梯度会差 N 倍，先看量级差多少——差整数倍的话基本就是这里出了问题
2. **矩阵转置**：`W1` 我们存的是 `(H, D)`，前向是 `X @ W1.T`，反向 `dW1 = dz1.T @ X`，如果某处忘了 `.T`，形状会对不上或数值错，检查这个问题可以打印每个量的 shape 对照看
3. **广播**：`db1` 要对上 batch 维 `sum(axis=0)`，如果直接 `dz1`（没求和）就是形状 `(N,H)` 而不是 `(H,)`，检查这个问题也可以打印每个量的 shape 对照来看
4. **公式本身**：逐项打印中间梯度的数值（dz2、dh、dz1），定位是从哪一步开始偏的

经验：**先看量级（如果差整数倍→求平均），再看形状（转置/广播），最后看数值（公式）**

### 5. 完成两次验证后，怎么理解 `loss.backward()`？它替我们做了什么？

`loss.backward()` 其实就是一个**自动反向传播机制**，它替我们做了：

1. **建计算图**：前向时记录了每个 op（matmul、add、relu、sigmoid...）及其依赖关系
2. **缓存中间值**：保存反向要用的各层输入/输出（对应第 1 问）
3. **查导数表**：每个 op 都有预定义的本地导数（比如 matmul 的导数是交换相乘）
4. **拓扑排序 + 链式相乘**：从 loss 出发，按逆拓扑序逐节点"上游梯度 × 本地导数"，把梯度累加到每个 `requires_grad=True` 参数的 `.grad` 上

我们手写的 `dz2→dh→dz1→dW1` 这一串，PyTorch 在内部用同样的链式法则自动展开
所以本题 NumPy 手算和 autograd 完全对得上
实际上呢，**autograd 没有什么特别的，就是把我们手算的链式法则自动化了而已**

### 6. 遇到的报错 / 不理解的点

- 一开始 batch 版本的 `dW1 = dz1.T @ X` 形状对不上，后来发现是 X 忘了广播 `np.atleast_2d`，单样本时 X 是 `(2,)` 导致 `(4,1)@(2,)`  出错，统一成二维后正常计算
- 对"loss 要不要除以 N"犹豫过，后面发现 PyTorch 默认 mean 后，NumPy 这边也除以N `dz2 = (p-y)/N` 才和它对上
